## T0 能让真实老人用起来

### T0-1 主持人 prompt 独立成 Agent
**背景**：反馈要求像窦文涛那样的高明主持人：顺着话聊、不让话掉在地上、适时引导多说。现在 `HOST_PROMPT` 同时管开场、选题、追问、安抚，没有独立的"主持人风格"层。
**要做**
- 把主持人风格拆成单独 prompt 文件（`app/server/host-prompt.*`），与选题、档案注入分开，可单独迭代和评测。
- 核心手法（每轮至少用一种）：
  1. 接住：抓老人上一句里一个具体细节（人、物、地名、数字）往下问，不跳走。
  2. 时代引子：用时代背景帮老人想起来，如"那会儿买肉还要肉票吧"。必须是通识，不编造老人的经历。
  3. 留白与捧场：老人在说就只给"嗯""后来呢"，不急着总结或换题。
  4. 适时引导：老人答得短，用画面或物件提一个具体小问题；答得长，两句话复述后再问。
  5. 不掉地上：老人提到的新人名、新地名、情绪词，在后面 2–3 轮内至少回扣一次。
- 红线（来自 vision）：不讲"自己的经历"，不替老人说感受，不加工情感；老人谈起遗忘的恐惧时倾听接住，不说教、不给虚假安慰；每句不超 20 字、最多三句、一次一问（沿用现有约束）。
**验收**
- 准备 10 段不同类型的老人回答（长、短、卡壳、跑题、谈遗忘、谈已故亲人），人工逐条评分：是否接住细节、是否复述、是否越界编造，达标率 ≥ 80%。
- 现有 `test/` 通过；防复述计划问题的服务端检查保留。
**依赖**：无。

### T0-2 持久化存储
**背景**：Render 免费档 `DATA_DIR=/tmp`，重启即清空；老人录音和故事不能丢（vision 第一原则是原声）。
**要做**：SQLite 文件和 `audio/` 迁到持久盘（Render 付费档加 disk，或同类平台），保留 `export.zip` 导出能力。
**验收**：重新部署、手动重启后，已有老人、访谈、原声、故事全部还在。
**依赖**：服务器预算，约 $7/月起。

### T0-3 HTTPS 线上地址与真机走查
**背景**：tasks.md 里"部署 HTTPS""真机走查"两项一直未勾。
**要做**
- 线上 HTTPS 地址稳定可访问。
- 安卓 Chrome 与 iOS Safari 各走完一次完整流程：建档、访谈、故事、家人收听。
- 记录真实人声（含方言口音）的转写质量与每轮延迟。
**验收**：两端都能录音、播放；走查问题清单落在 `docs/`，P0 级问题清零；延迟数据记录在案。
**依赖**：T0-2。

### T0-4 实时轮次延迟
**背景**：目标"老人说完到听见第一声 ≤ 4 秒"，瓶颈在合并调用本身 2–7 秒不稳，还有 429 配额问题。
**要做**：申请配额或确认可用的稳定模型；统计真机延迟分布，记录 P50/P90。
**验收**：真机 P50 ≤ 4s，P90 ≤ 7s，无连续 429。
**依赖**：T0-3。

## T1 产品形态完整（对应 UI/UX 反馈）

### T1-1 家人端框架：对话式主界面 + 侧边栏
**背景**：反馈要求"类似 OpenAI/豆包，点进来就是对话框"，点其他入口要看到登录后的效果（历史、个人信息、设置）。vision 要求"像记忆册，不像 AI 工具"，所以只改家人端，老人端不动。
**要做**
- 家人端首页：对话框 + 开始对话按钮。
- 侧边栏：历史记录（按访谈日期和话题）、记忆库、人生地图、记忆档案、设置。
- 视觉保持记忆册气质（暖色、衬线字、纸感），不套 ChatGPT 蓝灰。
- 老人端保持"大字 + 大麦克风 + 纯语音"，不做文字气泡。
**验收**：手机宽度下可用；老人端首屏不出现任何家人端菜单；截图评审通过（沿用 `app/screenshots/ui-review/` 流程）。
**依赖**：与 vision 的"温暖而不花哨"原则对齐，Tammy 确认视觉方向。

### T1-2 模拟登录与账号页（前端）
**要做**
- 登录页、个人信息页、设置页（称呼、通知、默认声音、数据导出入口）。
- "登录"先只写本地标记，不接后端，用于演示登录后的完整效果。
- 页面上不假装有安全能力：不显示"已加密保护"之类未实现的文案。
**验收**：未登录进入引导页，登录后进入框架；刷新后状态保留；清除后回到未登录。
**依赖**：T1-1。

### T1-3 转写存档层：带标签和时间戳
**背景**：三层存储第 2 层要求逐句保留原始转写、音频片段、时间戳、情绪。现在转写由 Gemini 合并调用顺带产出，没有稳定的时间戳和声音事件。
**要做**
- 评估并接入独立 ASR 存档（候选：SenseVoice 出文字、情绪、笑声等声音事件；Qwen3-ASR 加 ForcedAligner 出逐字时间戳）。
- 对话链路不变，ASR 作为旁路写入第 2 层，不增加首声延迟。
- 故事里可引用事件，如"说到这里老人笑了"，点句子回放对应原声片段。
**验收**
- 用同一批 10 段真实老人录音（含方言）对比三者：Gemini 现状、SenseVoice、Qwen3-ASR 的字错率与标签可用性，结论写入 `docs/`。
- 选定方案后，每条访谈句子都有起止时间戳，可回放。
**依赖**：阿里云 API key；T0-3 提供真实录音样本。

## T2 多家庭运营基础

### T2-1 真登录与家庭数据隔离
**背景**：现有数据表没有用户或家庭层，所有数据默认属于一位老人。
**要做**
- 子女账号注册登录（方式待定：邮箱魔法链接、手机验证码、微信，见"待决"）。
- 数据模型新增 家庭 → 老人 → 访谈；所有 `/api` 校验登录身份和家庭归属。
- 老人端设备绑定：子女扫码或邀请链接绑定一次，之后老人打开即进访谈，不用登录。
- 家人可邀请其他亲属以只读身份收听。
**验收**：A 家庭账号请求 B 家庭老人的任何接口都返回 403/404（自动化测试覆盖）；老人设备清除绑定后无法访问。
**依赖**：T0-2、T1-2。

### T2-2 数据库与录音存储升级
**要做**：sql.js（整库在内存）换为 Postgres；音频迁到对象存储（R2、Supabase Storage 或 OSS）；写迁移脚本，保持 `export.zip` 可用。
**验收**：并发 10 位用户同时访谈无数据丢失；迁移前后数据逐条核对一致。
**依赖**：T2-1 的数据模型。

### T2-3 合规与数据出境
**背景**：阿尔茨海默症属健康信息，按《个人信息保护法》是敏感个人信息；Gemini 与海外存储涉及数据出境。
**要做**：单独同意流程、隐私政策、数据删除与导出；确定面向国内用户时的模型与存储部署方案。
**验收**：收真实数据前，有书面方案并经 Tammy 确认。必要时请法务评审，这一条我不能代替专业意见。
**依赖**：T2-1。

### T2-4 实时语音对话实验（Qwen-Omni-Realtime）
**背景**：想评估端到端或全双工语音能否替代当前"录音、转写、LLM、TTS"链路。搜到的阿里资料没有写全双工，只有实时流式接口，此项是实验，不是承诺。
**要做**：做一个与现有链路并行的最小原型，对比：首声延迟、抢话率（老人停顿时被打断的次数）、对主持人 prompt 约束的遵守程度。
**验收**：用同样 10 段对话脚本，出一份对比报告和是否切换的建议。抢话率明显更高、或红线（编造经历、说教）遵守变差，则不切换。
**依赖**：T0-1（需要固定的主持人 prompt 作为对照）、T1-3 的评测样本。
