# 页面结构与文稿存储方案（2026-10-24，待 Tammy 确认）

## 两种使用者，两套入口
- 老人端：只有「开始聊天」一个大按钮，进去就是访谈，没有任何导航
- 家人端：管理和收听

## 页面
1. 首页（家人）：老人头像+称呼、「开始今天的聊天」大按钮（显示今天要聊的话题，可点换）、最近的记忆故事、人生地图完成度
2. 访谈页（老人）：AI 当前一句大字+朗读、超大麦克风、「再听一遍」「休息一下」；无菜单
3. 访谈结束页：生成的记忆故事、下次预告、「分享给家人」
4. 记忆库：故事卡片列表，可按人物/时期/话题筛选
5. 故事详情：标题、正文（每段旁有播放按钮听原声）、关键人物、时间地点、原话摘录、「查看完整访谈稿」
6. 人生地图：时间×关系×领域的覆盖情况，点空白处可指定下次聊
7. 记忆档案：人物关系、地点、物件、时间线（家人可补充/纠正，纠正不覆盖老人原话）
8. 老人资料：称呼、出生年份、家乡、重要人物（含已故标注）、老照片/老物件上传

## 文稿三层存储（一层都不丢）
- 第 1 层 原声：每次访谈完整录音 + 每句回答的音频片段
- 第 2 层 访谈稿：逐轮记录 [AI 问句、老人原始转写、整理后文本、音频片段、时间戳、所属话题节点、层次、情绪]，永不修改
- 第 3 层 加工成果：记忆故事（引用第 2 层的句子 id，可回溯原声）、记忆档案实体表（每条注明出处句子）
原则：上层可以重新生成，下层是原始证据；家人修改只写在第 3 层并留痕。
导出：每位老人可一键打包下载（原声 + 访谈稿 + 故事），数据归家人所有。
