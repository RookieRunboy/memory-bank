# 人生访谈框架 v3（问题库，2026-11-07）

> 与 app/src/framework.json 内容一致，前端读 JSON，本文件给人看（2026-11-07 起手工与 JSON 保持一致，原生成脚本不在仓库里）。变量沿用 docs/interview.md：{称呼}{姓名}{出生年份}{家乡}{重要人物}。所有问题一次一问、可直接朗读。

## 一、定位

这是一个**问题库**，不是人生的清单。人生不该被预先切成阶段、再逐项打勾，所以：

- 不预设年龄段（少年、青年、壮年这些），不记“聊过几成”，也不把没讲过的地方当成空白去补。老人没提到的时期和话题，就不主动问。
- 记下来的是老人讲过的内容：原话、人、地、物、他自己说的时间（“十几岁那会儿”“厂里那几年”）。
- 小忆先听老人讲到了什么，再从问题库里拿合适的问法。没有线索可跟时，只用轻松的话题（吃食、老歌、节日）起个头，或者直接问老人想聊什么。
- 每个话题有四层问题，由浅入深：1 事实，2 场景细节，3 感受，4 想对后辈说的话。深度只用来决定要不要往下问，不当成完成度展示给老人。

话题（节点）的标签只用来找相关问题：

- 每个节点带三类标签：人际关系、人生领域、触发物。关系可为空，触发物可多个，作为可选开场入口。
- 每个节点还有 entity_hints（用来和记忆档案里的人、地、物匹配）、敏感提示、是否需要情绪平稳（needs_calm）。
- 节点 id 里的 child、teen、youth、midlife、elder 前缀只是命名习惯，不代表年龄段，程序不读它。

- 人际关系（relation）：父母（parents，6 个节点）、兄弟姐妹（siblings，2 个节点）、爱人（spouse，4 个节点）、子女孙辈（children，5 个节点）、朋友同学（friends，5 个节点）、老师师傅（teachers，2 个节点）、同事（colleagues，3 个节点）
- 人生领域（domain）：上学（school，4 个节点）、工作（work，5 个节点）、家庭生活（family，17 个节点）、兴趣手艺（craft，5 个节点）、住过的地方（places，8 个节点）、时代大事（times，3 个节点）
- 触发物（trigger）：老照片（photo，12 个节点）、老歌（song，4 个节点）、家乡菜（food，8 个节点）、老物件（object，10 个节点）、节日（festival，3 个节点）

共 42 个节点。

## 二、层次规则

- 每个节点由浅入深四层：1 事实，2 场景细节，3 感受，4 想对后辈说的话。每层一个入场问题，一次只问一个
- 老人对某层问题给出实质回答，或自己主动讲到了那层的内容，就算到达该层，depth 取已到达的最大层
- 可以跳层：老人一开口就讲感受，直接记 depth 3，回头再补场景也行
- 老人手边有触发物（照片、老歌、菜、物件、节日）并点了出来，用 trigger_openers 里对应的问题代替第 1 层开场，老人回答后照常从第 1 层或第 2 层接着走
- 第 4 层只在老人情绪愉快、平稳时问；老人难过时停在第 3 层，不追问

## 三、聊够了的标准

- deep：depth 到达 4，即四层都聊到
- short_replies：老人在本节点连续三次简短回答（前两次先降难度：具体小问题、再换提示物），每次少于八个字，或说不知道、忘了
- tired：老人表现出疲倦、烦躁，或说累了、不想说了
- upset：出现悲伤或困惑，安抚后仍未恢复，立刻离开节点，并标记 sensitive
- max_turns：本节点已问满八轮

#### 老家的房子（child-home）
- 标签：关系 无；领域 住过的地方；触发物 老照片、老物件
- 匹配线索：老家、房子、院子
- 第1层 事实：{称呼}，您小时候在{家乡}住的房子，是什么样子的呀？
- 第2层 场景细节：下雨天，屋里屋外是什么样的？
- 第3层 感受：一想起那个家，您心里是什么滋味？
- 第4层 想对后辈说的话：关于老家，您想让孙辈知道点什么？
- 触发物开场（老照片）：这张老照片上的房子，是您小时候的家吗？
- 敏感提示：可能涉及贫困或饥荒年代。不追问挨饿受苦的细节，说那时候大家都不容易，您真了不起，再问一件开心的小事。

## 五、话题状态

只记老人讲到哪，不记完成度。没讲过的话题没有记录，也不会被当成待补的空白。

- 每个话题记录：depth（讲到的最深一层，0 到 4，0 表示还没讲过）、enough（聊够了）、turns、notes（每轮一句要点）、sensitive、lastSessionId、updatedAt。
- 更新规则：
  1. 每轮老人回答后，判断这轮到达了第几层，depth 取最大值，turns 加一，并把一句要点追加到 notes
  2. depth 到达 4 或问满八轮，enough 置为 true
  3. 因 short_replies 或 tired 离开时，depth 已到 3 则 enough 置为 true，否则保持原样
  4. 因 upset 离开时 sensitive 置为 true；之后不主动提，只有老人自己提起才再聊
  5. 老人跑题讲到别的话题，把这段内容记到那个话题下，更新它的 depth 和 notes，不打断老人；没有合适话题时记到最接近的
  6. 每轮从老人话里抽取人、地、物，写入记忆档案 entities，记下来源话题
  7. depth 只前进不后退
- 旧数据兼容：早期记录里的 status 为 done 的，读取时按 enough 处理。

## 六、记忆档案实体

- 记忆档案里的人、地、物，用来顺藤摸瓜选下一个节点。字段：
  - type：person、place、thing 三选一
  - relation：人物与老人的关系，取 dimensions.relation 的值
  - trigger：物品可对应的触发物类型，可选
  - deceased：是否已故，已故人物只走美好回忆
  - sourceNodes：在哪些节点里提到过
  - lastSessionId：最近一次提到的访谈
- 实体到节点的匹配：
  - 人物实体：用 relation 匹配节点 tags.relation，用 name 和 aliases 匹配节点 entity_hints
  - 地点实体：匹配 tags.domain 为 places 的节点，以及 entity_hints
  - 物品实体：用 trigger 匹配节点 tags.trigger，用 name 匹配 entity_hints
  - 也可以把实体和候选节点标题交给模型判断相关性

## 七、选话题规则

不预设今天聊几个话题：老人选一个话题走深，聊够了再给候选让他选。

- 选题顺序：
  1. 指定：老人从首页点了触发物（老照片、老歌、家乡菜等），或选了某个话题，就用它。只给了触发物时，选 tags.trigger 包含它、且没聊够的话题，用对应的 trigger_openers 开场
  2. 顺藤摸瓜：取记忆档案里 lastSessionId 为上次访谈的实体，按 archive.match_rules 找相关且老人还没讲过的话题。例如上次讲到李建国和自行车，就选 youth-wedding 或 youth-newhome
  3. 加深：老人讲过一些、还没聊够的话题（depth 小于 4），选 lastSessionId 最近的，从 depth 加一层接着问
  4. 没有线索可跟：只用轻松的话题（fallback_safe_nodes：吃食、老歌、节日）起头。不去补哪个年龄段、哪类关系还空着
  5. 每一步都先排除：sensitive 的话题；needs_calm 的话题，除非老人主动聊到；档案缺少前提的话题，例如没填爱人跳过 relation 为 spouse 的，没有子女跳过 relation 为 children 的
  6. 有多个候选时，优先选 relation 和 domain 都与上一个话题不同的；没有，就选至少一个不同的
  7. 轻松话题也聊过了，就回到老人讲得最开心的话题，挑 notes 里一个细节再聊一层
- 候选：小忆问候后念 3 个候选，屏幕同时显示大卡片。一个顺着上次线索或加深，其余是轻松话题；避开敏感与需平静的话题。老人点卡片或用语音选，可以“换几个”（不重复），也可以“想聊什么都行”自由聊，按内容归档。一个话题聊够后同样给候选，并可“继续聊这个”或“今天先到这”。
- 结束时不预告下次聊什么。
- 需要情绪平稳的话题：teen-times、youth-times、midlife-hard、midlife-parents-old。
- 安全退路话题：elder-hometown-food、child-food、elder-songs、child-newyear，出现情绪时转向这些。
- 跑题处理：老人讲到别的话题时，主持人顺着聊，不拉回。后台把这几轮归到最匹配的话题下，并抽取实体。老人讲完后，主持人用一句过渡回到当前话题，或者顺势把那个话题当作今天的下一个。
