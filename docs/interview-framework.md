# 人生访谈框架 v2（多维话题网，2026-10-24）

> 与 app/src/framework.json 内容一致（由 /workspace/fw/gen.py 生成），前端读 JSON，本文件给人看。变量沿用 docs/interview.md：{称呼}{姓名}{出生年份}{家乡}{重要人物}。所有问题一次一问、可直接朗读。

## 一、结构

- 话题网由节点组成。每个节点带四个维度的标签：时间、人际关系、人生领域、触发物。时间、关系、领域各取一个值（关系可为空），触发物可多个，作为可选开场入口。
- 每个节点由浅入深四层：1 事实，2 场景细节，3 感受，4 想对后辈说的话。每层一个问题。
- 每个节点还有 entity_hints（用来和记忆档案里的人、地、物匹配）、敏感提示、是否需要情绪平稳（needs_calm）。

- 时间（time）：儿童（child，8 个节点）、少年（teen，7 个节点）、青年（youth，10 个节点）、中年（midlife，9 个节点）、老年（elder，8 个节点）
- 人际关系（relation）：父母（parents，6 个节点）、兄弟姐妹（siblings，2 个节点）、爱人（spouse，4 个节点）、子女孙辈（children，5 个节点）、朋友同学（friends，5 个节点）、老师师傅（teachers，2 个节点）、同事（colleagues，3 个节点）
- 人生领域（domain）：上学（school，4 个节点）、工作（work，5 个节点）、家庭生活（family，17 个节点）、兴趣手艺（craft，5 个节点）、住过的地方（places，8 个节点）、时代大事（times，3 个节点）
- 触发物（trigger）：老照片（photo，12 个节点）、老歌（song，4 个节点）、家乡菜（food，8 个节点）、老物件（object，10 个节点）、节日（festival，3 个节点）

共 42 个节点。

## 二、层次规则

- 每个节点由浅入深四层：1 事实，2 场景细节，3 感受，4 想对后辈说的话。每层一个入场问题，一次只问一个
- 老人对某层问题给出实质回答，或自己主动讲到了那层的内容，就算到达该层，depth 取已到达的最大层
- 可以跳层：老人一开口就讲感受，直接记 depth 3，回头再补场景也行
- 家人提供了触发物（照片、老歌、菜、物件、节日），用 trigger_openers 里对应的问题代替第 1 层开场，老人回答后照常从第 1 层或第 2 层接着走
- 第 4 层只在老人情绪愉快、平稳时问；老人难过时停在第 3 层，不追问

## 三、聊够了的标准

- deep：depth 到达 4，即四层都聊到
- short_replies：老人在本节点连续两次简短回答，每次少于八个字，或说不知道、忘了
- tired：老人表现出疲倦、烦躁，或说累了、不想说了
- upset：出现悲伤或困惑，安抚后仍未恢复，立刻离开节点，状态记为 partial 并标记 sensitive
- max_turns：本节点已问满八轮

## 五、节点状态

- status：not_started 未聊；partial 聊过一些；done 聊完。depth：0 到 4，表示到达的最深层。
- 每个节点记录：status、depth、turns、notes、sensitive、lastSessionId。
- 更新规则：
  1. depth 为 0 时 status 为 not_started；老人第一次有实质回答，depth 至少为 1，status 变为 partial
  2. 每轮老人回答后，判断这轮到达了第几层，depth 取最大值，turns 加一，并把一句要点追加到 notes
  3. depth 到达 4 或问满八轮，status 置为 done
  4. 因 short_replies 或 tired 离开时，depth 已到 3 则置为 done，否则保持 partial
  5. 因 upset 离开时保持 partial，并把 sensitive 置为 true；之后自动选题跳过，只有老人主动提起或家人指定才再聊
  6. 老人跑题讲到别的节点，把这段内容记到那个节点下，更新它的 depth 和 notes，不打断老人；没有合适节点时记到最接近的节点，并在 notes 里注明
  7. 每轮从老人话里抽取人、地、物，写入记忆档案 entities，记下来源节点
  8. 状态和 depth 只前进不后退，家人可以手动重置

## 六、记忆档案实体

- 记忆档案里的人、地、物，用来顺藤摸瓜选下一个节点。字段：
  - type：person、place、thing 三选一
  - relation：人物与老人的关系，取 dimensions.relation 的值
  - trigger：物品可对应的触发物类型，可选
  - deceased：是否已故，已故人物只走美好回忆
  - sourceNodes：在哪些节点里提到过
  - lastSessionId：最近一次提到的访谈
- 实体到节点的匹配：
  - 人物实体：用 relation 匹配节点 tags.relation，用 name 和 aliases 匹配节点 entity_hints
  - 地点实体：匹配 tags.domain 为 places 的节点，以及 entity_hints
  - 物品实体：用 trigger 匹配节点 tags.trigger，用 name 匹配 entity_hints
  - 也可以把实体和候选节点标题交给模型判断相关性

## 七、会话规划规则

- 每次节点数：1到2个节点，路演默认1个节点走深，再视情况进第2个。
- 选题算法：
  1. 第一步，家人指定：家人指定了节点或触发物，就用指定的，跳过后面步骤（敏感节点也允许家人指定）。只给了触发物时，选 tags.trigger 包含它、且 status 不是 done 的节点，用对应的 trigger_openers 开场
  2. 第二步，顺藤摸瓜：取记忆档案里 lastSessionId 为上次访谈的实体，按 archive.match_rules 找相关且 status 为 not_started 的节点。例如上次讲到李建国和自行车，就选 youth-wedding 或 youth-newhome
  3. 第三步，加深：找 status 为 partial 且 depth 小于 4 的节点，选 lastSessionId 最近的，从 depth 加一层接着问
  4. 第四步，兜底补覆盖：统计已聊节点（partial 或 done）在 relation、domain、time 三个维度上每个取值的数量，找出数量最少的那个取值，同样少时按 relation、domain、time 的维度顺序，再按 dimensions 里取值的顺序；在带这个取值的 not_started 节点里，按 nodes 列表顺序取第一个
  5. 每一步都先排除：sensitive 为 true 的节点；needs_calm 节点，除非老人情绪平稳且主动聊到；档案缺少前提的节点，例如没填爱人跳过 relation 为 spouse 的节点，没有子女跳过 relation 为 children 的节点
  6. 避免连续两次同一维度：每一步有多个候选时，优先选 relation 和 domain 都与上一个节点不同的；没有，就选至少一个维度不同的；仍然没有，才用同维度的。同一次访谈里的两个节点也照此错开
  7. 所有节点都 done，就回到老人讲得最开心的节点，挑 notes 里一个细节再聊一层
  8. 下次节点 next_node 用同样算法，在假设今天节点都已 done 的前提下预先算出，用于结束语预告
- 需要情绪平稳的节点：teen-times、youth-times、midlife-hard、midlife-parents-old。
- 安全退路节点：elder-hometown-food、child-food、elder-songs、child-newyear，出现情绪时转向这些。
- 跑题处理：老人讲到别的节点时，主持人顺着聊，不拉回。后台把这几轮归到最匹配的节点下，并抽取实体。老人讲完后，主持人用一句过渡回到当前节点，或者顺势把那个节点当作今天第二个节点。
